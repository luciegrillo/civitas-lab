# Civitas Lab v0.2.0

Civitas Lab v0.2.0 turns the verified synchronous baseline into a versioned
experimental comparison of update schedules. It adds one precisely specified
random-sequential mechanism, separates initialization and scheduling random
streams, publishes a predeclared paired study, and produces standalone HTML
experiment reports without changing the published schema `0.1` artifact
contract.

## Highlights

### Explicit update scheduling

- `SYNCHRONOUS` retains the verified double-buffered generation semantics.
- `RANDOM_SEQUENTIAL` performs one shuffled sweep without replacement per tick,
  recomputes candidate payoffs from the current lattice, and writes each
  selected strategy immediately.
- Both engines implement the same small simulation contract and remain
  independently testable.

### Versioned schema and paired seeds

- Schema `0.2` requires every scenario to declare its update schedule.
- Initialization seed derivation remains compatible with schema `0.1`.
- A separate `schedule` seed domain controls shuffled site orders.
- Paired synchronous and random-sequential runs therefore share generation zero
  without sharing their random streams.

### Scheduling-robustness study

The release includes a predeclared 400-run comparison on a `15 x 15` toroidal
lattice with ten temptation values and 20 paired replicates per value.

Within this bounded grid, random-sequential updating produces a lower median
final cooperator fraction at every tested temptation value. At `b=1.85` and
`b=1.95`, every random-sequential run reaches all-defect by tick 100, while 85%
of synchronous runs remain mixed. The effect is not monotonic across the full
grid, and the documented claims remain limited to the implemented mechanisms
and declared parameters.

### Self-contained reports

Schema `0.2` outputs include `report.html` with:

- scenario design and update schedules;
- selected aggregate distribution statistics;
- all experiment-level PNG figures embedded directly in the file;
- the resolved JSON configuration;
- reproduction and validation commands;
- SHA-256 manifest coverage.

The report uses inline CSS only and contains no JavaScript, remote assets,
analytics, or frontend runtime.

### Safer artifact publication

Experiment artifacts are assembled in an isolated staging directory and moved
into place only after runs, aggregates, figures, reports, and checksums succeed.
Existing output remains intact during overwrite execution and is restored if
publication fails.

## Compatibility

- Existing schema `0.1` configurations remain synchronous.
- Their initialization seeds, CSV headers, scientific results, and artifact set
  remain unchanged.
- Schema `0.1` does not generate `report.html`.
- Schema `0.2` adds schedule-aware metadata, CSV columns, and HTML reports.

## Assets

- `civitas-lab-0.2.0.jar`: self-contained Java 25 command-line application.
- `civitas-lab-0.2.0-results.tar.gz`: complete validated outputs for the
  frequency, kaleidoscope, implementation-robustness, and
  scheduling-robustness experiments.
- `SHA256SUMS`: checksums for both release assets.

## Scientific Boundary

This release demonstrates scheduling sensitivity in one abstract spatial
weak Prisoner's Dilemma. It does not establish that random-sequential updating
universally reduces cooperation, that either schedule is generally correct for
social systems, or that Civitas Lab predicts real human behavior.

See the ODD description, scheduling protocol, scheduling results, and
limitations documentation for the complete mechanism and claim boundaries.
